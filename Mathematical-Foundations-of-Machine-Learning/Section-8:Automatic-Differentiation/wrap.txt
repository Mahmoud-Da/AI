*** 73. What Automatic Differentiation Is ***
# 1. What Is Automatic Differentiation?

**Automatic Differentiation (AD)** is a computational technique for calculating derivatives automatically through a sequence of mathematical operations.

It is especially useful in **machine learning**, where models can contain many inputs and extremely long chains of nested functions.

---

# 2. Different Names for Automatic Differentiation

The lecture gives several names:

| Name                              | Meaning                                               |
| --------------------------------- | ----------------------------------------------------- |
| **Automatic Differentiation**     | Full name                                             |
| **Autodiff**                      | Short form                                            |
| **Autograd**                      | Common name related to automatic gradient calculation |
| **Computational Differentiation** | Emphasizes the computational nature                   |
| **Algorithmic Differentiation**   | Another standard name                                 |
| **Reverse Mode Differentiation**  | Refers to the direction used by reverse-mode autodiff |

For this course, **Autodiff** and **Autograd** are especially important terms to recognize.

---

# 3. Why Not Just Use the Methods We Already Learned?

Before automatic differentiation, we studied two main approaches.

## 3.1 Numerical Differentiation

The **Delta method** is an example of numerical differentiation.

The basic idea is:

-------------------code----------------------
Take two nearby points
        ↓
Calculate Δy / Δx
        ↓
Make Δx increasingly small
        ↓
Approximate the derivative
-------------------code----------------------

For example:

-------------------code----------------------
def f(x):
    return x ** 2

x = 2
delta = 1e-6

derivative = (f(x + delta) - f(x)) / delta

print(derivative)
-------------------code----------------------

This gives an approximation close to:

-------------------code----------------------
4
-------------------code----------------------

### Problem

Numerical differentiation can introduce **rounding errors** when implemented computationally.

Therefore, although it works well for simple examples, it is not the preferred approach for large machine-learning computations.

---

# 4. Symbolic Differentiation

The second approach is **symbolic differentiation**.

This is what we primarily practiced in Segment 2.

For example:

[
y=x^2
]

Using the power rule:

[
\frac{dy}{dx}=2x
]

We could theoretically write software that implements rules such as:

* Constant rule
* Power rule
* Sum rule
* Product rule
* Quotient rule
* Chain rule

and then applies them to increasingly complicated expressions.

### Problem

This becomes **computationally inefficient** as functions become more complicated.

Machine-learning algorithms can contain:

-------------------code----------------------
Many operations
      ↓
Many nested functions
      ↓
Large computational graphs
      ↓
Very complicated derivatives
-------------------code----------------------

Symbolically manipulating all of those expressions can become impractical.

The lecture emphasizes that symbolic differentiation could work for simple functions, but becomes unsuitable for complex real-world machine-learning examples.

---

# 5. Why Automatic Differentiation?

Automatic differentiation provides a computationally convenient alternative.

According to the lecture, compared with the classical approaches, automatic differentiation:

* Avoids the rounding-error problem associated with numerical differentiation.
* Avoids the computational inefficiency of explicitly applying symbolic differentiation rules.
* Handles functions with **many inputs** well.
* Handles **higher-order derivatives** effectively.

This makes it particularly suitable for machine learning.

---

# 6. The Core Idea: Automatic Differentiation Uses the Chain Rule

The most important concept in this lecture is:

> **Automatic differentiation works by applying the chain rule to a sequence of arithmetic operations.**

The lecture describes this as a **forward pass of arithmetic operations**.

Consider two nested functions:

[
x \rightarrow u \rightarrow y
]

For example:

[
u=f(x)
]

and:

[
y=g(u)
]

The chain rule tells us:

The intermediate (du) effectively cancels:

-------------------code----------------------
dy   du
-- × --
du   dx

   ↓

dy
--
dx
-------------------code----------------------

This is the mathematical foundation that automatic differentiation uses.

---

# 7. Forward Pass

The forward computation proceeds from the input toward the output:

-------------------code----------------------
x
↓
u
↓
y
-------------------code----------------------

For example:

-------------------code----------------------
x = 2

u = x ** 2
y = u + 3

print(y)
-------------------code----------------------

The computation is:

-------------------code----------------------
x = 2
 ↓
u = 4
 ↓
y = 7
-------------------code----------------------

This is the **forward pass**.

---

# 8. How Automatic Differentiation Moves Through the Computation

Here is the important distinction.

When we manually applied the chain rule in Segment 2, we generally started from the **innermost function**.

For example:

-------------------code----------------------
x → u → y
-------------------code----------------------

we might start by differentiating:

-------------------code----------------------
u with respect to x
-------------------code----------------------

and then:

-------------------code----------------------
y with respect to u
-------------------code----------------------

Automatic differentiation, specifically **reverse-mode differentiation**, works in the opposite direction.

It proceeds:

-------------------code----------------------
y
↓
u
↓
x
-------------------code----------------------

This is why the lecture calls it **reverse mode differentiation**.

---

# 9. Reverse-Mode Automatic Differentiation

The basic idea is:

-------------------code----------------------
Forward computation:

x → u → y


Reverse differentiation:

y → u → x
-------------------code----------------------

The derivatives from the different stages are chained together.

Conceptually:

-------------------code----------------------
Forward:
x ─────→ u ─────→ y

Reverse:
∂y/∂x ← ∂y/∂u ← ∂u/∂x
-------------------code----------------------

The goal is ultimately to calculate:

[
\frac{dy}{dx}
]

---

# 10. Why Reverse Mode Is Computationally Useful

One of the major advantages described in the lecture is computational efficiency.

Suppose the forward pass is:

-------------------code----------------------
x → u → y
-------------------code----------------------

Automatic differentiation performs the derivative calculation backward:

-------------------code----------------------
y → u → x
-------------------code----------------------

The lecture explains that the additional computational cost is only a **small constant factor** compared with the original forward pass.

Conceptually:

-------------------code----------------------
Forward computation
        ↓
   relatively cheap
        ↓
Reverse-mode autodiff
        ↓
Only a small constant-factor overhead
-------------------code----------------------

This is one of the reasons automatic differentiation is so useful for machine learning.

---

We can represent the mathematical idea manually:

-------------------code----------------------
# Forward pass

y = u ** 3

print("x:", x)
print("u:", u)
print("y:", y)
-------------------code----------------------

The computation is:

-------------------code----------------------

The chain rule would conceptually give:

-------------------code----------------------

-------------------code----------------------

For this example:

-------------------code----------------------

-------------------code----------------------

and therefore:

-------------------code----------------------

-------------------code----------------------

The important point for this lecture is not manually calculating the derivative, but recognizing that **automatic differentiation can computationally track this chain**.

-------------------code----------------------

*** 74. Autodiff with PyTorch ***
# 1. Automatic Differentiation with PyTorch

This lecture is the first hands-on demonstration of **Automatic Differentiation (Autodiff)** using **PyTorch**.

The goal is simple:

> Calculate the derivative/slope of (y=x^2) at (x=5) using PyTorch, and verify that it matches the result we get manually.

---

# 2. The Mathematical Problem

We start with:

[
y=x^2
]

We want to find the slope at:

[
x=5
]

From the **power rule**:

[
\frac{dy}{dx}=2x
]

Therefore:

[
\frac{dy}{dx}\bigg|_{x=5}=2(5)=10
]

So we already know the expected answer:

-------------------code----------------------
Slope = 10
-------------------code----------------------

The purpose of PyTorch is to calculate this automatically rather than manually applying the derivative rules.

---

# 3. Import PyTorch

First, import the PyTorch library.

-------------------code----------------------
import torch
-------------------code----------------------

PyTorch is commonly thought of as a deep-learning library, but the lecture emphasizes that it is broader than just neural networks.

It can also be used for **automatic differentiation and calculus operations**.

---

# 4. Create the Input Tensor

We create a scalar tensor containing our (x) value:

-------------------code----------------------
x = torch.tensor(5.0)
-------------------code----------------------

The decimal point is intentional.

The lecture emphasizes using a **float tensor**, because many PyTorch operations work properly with floating-point tensors.

We can inspect it:

-------------------code----------------------
print(x)
-------------------code----------------------

Output:

-------------------code----------------------
tensor(5.)
-------------------code----------------------

---

# 5. Enable Gradient Tracking

This is the important new concept.

We want PyTorch to calculate derivatives with respect to `x`.

Therefore, we tell PyTorch to track the gradient of `x`:

-------------------code----------------------
x.requires_grad_()
-------------------code----------------------

This changes:

-------------------code----------------------
x.requires_grad
-------------------code----------------------

from:

-------------------code----------------------
False
-------------------code----------------------

to:

-------------------code----------------------
True
-------------------code----------------------

You can verify it:

-------------------code----------------------
print(x.requires_grad)
-------------------code----------------------

Output:

-------------------code----------------------
True
-------------------code----------------------

### Why do we need this?

PyTorch does **not** track gradients by default.

Gradient tracking requires additional memory, so it is only enabled when we need derivatives.

---

# 6. Perform the Forward Pass

Now implement our function:

[
y=x^2
]

In PyTorch:

-------------------code----------------------
y = x**2
-------------------code----------------------

Conceptually, the forward pass is:

-------------------code----------------------
x → y
-------------------code----------------------

or:

-------------------code----------------------
5 → 25
-------------------code----------------------

We can verify:

-------------------code----------------------
print(y)
-------------------code----------------------

Output:

-------------------code----------------------
tensor(25., grad_fn=...)
-------------------code----------------------

The important idea is that PyTorch has tracked the operation that produced `y` from `x`.

---

# 7. Gradient Tracking Is Contagious

This is an important concept from the lecture.

Because `x` has gradient tracking enabled:

-------------------code----------------------
x.requires_grad_()
-------------------code----------------------

tensors created as a result of operations involving `x` will also track the necessary gradient information.

For example:

-------------------code----------------------
y = x**2
-------------------code----------------------

PyTorch knows that `y` was created from `x`.

Therefore, it has enough information to work backwards from `y` toward `x`.

Conceptually:

-------------------code----------------------
Forward:

x ──────→ y
5         25


Backward:

dy/dx
←───────
-------------------code----------------------

This is the basis of Autodiff.

---

# 8. Calculate the Derivative with `backward()`

Now we perform automatic differentiation.

-------------------code----------------------
y.backward()
-------------------code----------------------

The `backward()` method tells PyTorch to work backwards from `y` and calculate the gradients.

In this example, we want:

[
\frac{dy}{dx}
]

PyTorch therefore follows the computational path:

-------------------code----------------------
y → x
-------------------code----------------------

and calculates the gradient automatically.

---

# 9. Retrieve the Gradient

After calling:

-------------------code----------------------
y.backward()
-------------------code----------------------

we can access the gradient stored on `x`:

-------------------code----------------------
print(x.grad)
-------------------code----------------------

The result is:

-------------------code----------------------
tensor(10.)
-------------------code----------------------

Therefore:

-------------------code----------------------
dy/dx = 10
-------------------code----------------------

This matches our manual calculation exactly.

---

# 10. What PyTorch Did

Let's compare the two approaches.

### Manual differentiation

We started with:

-------------------code----------------------
y = x²
-------------------code----------------------

Applied the power rule:

-------------------code----------------------
dy/dx = 2x
-------------------code----------------------

Substituted:

-------------------code----------------------
x = 5
-------------------code----------------------

Result:

-------------------code----------------------
dy/dx = 10
-------------------code----------------------

### PyTorch Autodiff

We:

-------------------code----------------------
x = torch.tensor(5.0)
x.requires_grad_()

y = x**2

y.backward()

print(x.grad)
-------------------code----------------------

Result:

-------------------code----------------------
10
-------------------code----------------------

So both approaches produce the same result.

---

# 11. Why This Becomes Powerful in Machine Learning

The example is intentionally extremely simple:

-------------------code----------------------
x → x² → y
-------------------code----------------------

But the same idea can be applied to much more complicated computational chains.

For example:

-------------------code----------------------
x
 ↓
function 1
 ↓
function 2
 ↓
function 3
 ↓
...
 ↓
function 1000
 ↓
y
-------------------code----------------------

Manually differentiating hundreds or thousands of nested operations would be extremely difficult.

PyTorch can track the computational operations and then use:

-------------------code----------------------
y.backward()
-------------------code----------------------

to calculate the gradients automatically.

This becomes particularly useful in machine learning and deep learning.

# 15. Best Practices and Important Notes

### 15.1 Use floating-point tensors

For differentiation, follow the lecture's approach and use:

-------------------code----------------------
torch.tensor(5.0)
-------------------code----------------------

rather than:

-------------------code----------------------
torch.tensor(5)
-------------------code----------------------

The decimal makes the tensor floating-point.

### 15.2 Enable gradients only when needed

Gradient tracking consumes additional memory.

Use:

-------------------code----------------------
x.requires_grad_()
-------------------code----------------------

when you actually need to calculate derivatives.

### 15.3 `backward()` calculates gradients

The key operation is:

-------------------code----------------------
y.backward()
-------------------code----------------------

It propagates the gradient backward through the operations that produced `y`.

### 15.4 `.grad` contains the result

After:

-------------------code----------------------

-------------------code----------------------

-------------------code----------------------

        ↓

-------------------code----------------------

# 1. TensorFlow Automatic Differentiation

This lecture demonstrates how to calculate derivatives using **Automatic Differentiation (Autodiff)** in **TensorFlow**.

The problem is the same as in the previous PyTorch lecture:

[
y=x^2
]

Find the derivative:

[
\frac{dy}{dx}
]

at:

[
x=5
]

We already know manually that:

[
\frac{dy}{dx}=2x
]

so at (x=5):

-------------------code----------------------
dy/dx = 10
-------------------code----------------------

The goal is to make TensorFlow calculate this automatically.

---

# 2. Import TensorFlow

First, import TensorFlow:

-------------------code----------------------
import tensorflow as tf
-------------------code----------------------

TensorFlow provides automatic differentiation through its **GradientTape** mechanism.

---

# 3. Create the Input Tensor

Just like in PyTorch, we start by creating a scalar tensor containing `5`.

-------------------code----------------------
x = tf.Variable(5.0)
-------------------code----------------------

The important value is:

-------------------code----------------------
x = 5
-------------------code----------------------

We will calculate the derivative of `y` with respect to this `x`.

---

# 4. Use `GradientTape`

This is the main difference between TensorFlow and PyTorch.

In PyTorch, we enabled gradient tracking directly on the tensor:

-------------------code----------------------
x.requires_grad_()
-------------------code----------------------

TensorFlow instead uses a **gradient tape**:

-------------------code----------------------
with tf.GradientTape() as tape:
-------------------code----------------------

The basic structure is:

-------------------code----------------------
with tf.GradientTape() as tape:
    # operations whose gradients we want to track
-------------------code----------------------

The lecture emphasizes that gradient tracking in TensorFlow happens within this block rather than being enabled globally in the same way as PyTorch.

---

# 5. Tell TensorFlow What to Watch

Inside the `GradientTape`, we tell TensorFlow which variable we want to track:

-------------------code----------------------
tape.watch(x)
-------------------code----------------------

This is analogous to enabling gradient tracking for `x` in PyTorch.

Conceptually:

-------------------code----------------------
PyTorch:
x.requires_grad_()

TensorFlow:
tape.watch(x)
-------------------code----------------------

We are telling TensorFlow:

> Track the operations involving `x` so that we can later calculate derivatives with respect to `x`.

---

# 6. Perform the Forward Pass

Now calculate:

[
y=x^2
]

Inside the gradient tape:

-------------------code----------------------
with tf.GradientTape() as tape:
    tape.watch(x)
    y = x**2
-------------------code----------------------

The forward pass is:

-------------------code----------------------
x → x² → y
-------------------code----------------------

With:

-------------------code----------------------
x = 5
-------------------code----------------------

we get:

-------------------code----------------------
y = 25
-------------------code----------------------

TensorFlow's gradient tape records the operations needed to calculate the derivative.

---

# 7. Calculate the Derivative

After the forward calculation, we use:

-------------------code----------------------
tape.gradient(y, x)
-------------------code----------------------

This asks TensorFlow to calculate:

[
\frac{dy}{dx}
]

The complete operation is:

-------------------code----------------------
dy_dx = tape.gradient(y, x)
-------------------code----------------------

The result is:

-------------------code----------------------
10
-------------------code----------------------

Therefore:

-------------------code----------------------
dy/dx = 10
-------------------code----------------------

This matches:

1. The manual calculation.
2. The PyTorch calculation.

*** 76. The Line Equation as a Tensor Graph ***
# 1. Overview: From Calculus to Automatic Differentiation

This lecture begins the transition from **calculus by hand** to using **automatic differentiation (Autodiff)** inside machine learning.

The main goal is:

> Represent a machine-learning equation as a computational graph in PyTorch, so that automatic differentiation can later calculate how the output changes with respect to the model parameters.

The example is the simplest possible machine-learning model:

[
y = mx+b
]

where:

* (x) = input
* (y) = model output
* (m) = slope/weight parameter
* (b) = y-intercept/bias parameter

---

# 2. The Computational Graph

The equation

[
y = mx+b
]

can be represented as a **Directed Acyclic Graph (DAG)**.

### Nodes

The graph contains:

1. Input: (x)
2. Parameter: (m)
3. Multiplication: (m \times x)
4. Parameter: (b)
5. Addition: (mx+b)
6. Output: (y)

Conceptually:

-------------------code----------------------
x ─────┐
       × ─────┐
m ─────┘      +
              ├── y
b ────────────┘
-------------------code----------------------

### Edges

The arrows connecting the nodes are **directed edges**.

In this computational graph:

* Information flows in one direction.
* There are no loops/cycles.
* Therefore, it is a **directed acyclic graph**.

The edges carry tensors containing information such as:

-------------------code----------------------
x
m
m × x
b
y
-------------------code----------------------

---

# 3. Why Use a Computational Graph?

The important idea is that a machine-learning model can be represented as a sequence of operations.

For our line:

-------------------code----------------------
x
 ↓
m × x
 ↓
m × x + b
 ↓
y
-------------------code----------------------

This becomes especially powerful when the model contains hundreds or thousands of operations.

Instead of manually differentiating the entire equation, PyTorch can track the operations and later use automatic differentiation to calculate gradients.

---

# 4. The Machine-Learning Example

The lecture uses a simple regression problem.

The goal is to fit a straight line to data points.

The model is:

-------------------code----------------------
y = m * x + b
-------------------code----------------------

The model has only two parameters:

-------------------code----------------------
m = slope
b = y-intercept
-------------------code----------------------

The lecture deliberately starts these parameters with values that are not close to the correct answer so that we can observe the model learning.

Initial values:

-------------------code----------------------
m = 0.9
b = 0.1
-------------------code----------------------

These are intentionally near zero.

---

# 5. Why Initialize Parameters Near Zero?

A common machine-learning approach is to initialize model parameters with relatively small values.

For this simple example:

-------------------code----------------------
m = 0.9
b = 0.1
-------------------code----------------------

The lecture emphasizes that we **could** try to guess better values.

For example, visually we could see that:

* The data has a negative slope.
* The y-intercept appears to be around 2.

But doing this would make the demonstration artificially easy.

Instead, we start with values that don't fit the data well and allow the machine-learning process to improve them.

### Important idea

The point isn't merely to solve this tiny regression problem.

The important advantage is **scalability**.

The same general approach can scale from:

-------------------code----------------------
2 parameters + 8 data points
-------------------code----------------------

to models containing:

-------------------code----------------------
millions of parameters
millions/billions of data points
-------------------code----------------------

This is one of the major reasons gradient-based machine learning is so important.

---

# 10. Why `requires_grad` Matters

These gradients tell us how changing each parameter affects the output.

# 13. How This Connects to Automatic Differentiation

The computational graph allows PyTorch to remember the operations used to calculate (y).

For example:

-------------------code----------------------
m ──┐
    × ──> mx ──┐
x ──┘          +
               ├──> y

-------------------code----------------------

Conceptually:

[

]

We want to know:

[
\frac{\partial y}{\partial m}
]

and

[
\frac{\partial y}{\partial b}
]

Those gradients will eventually tell the optimization algorithm how to modify (m) and (b).

# 16. Important Best Practices

### 16.1 Use floating-point tensors

For this type of PyTorch calculation, use floats:

-------------------code----------------------

-------------------code----------------------

### 16.2 Track gradients only when needed

Gradient tracking has computational/memory costs.

For parameters that need differentiation:

-------------------code----------------------

-------------------code----------------------

### 16.3 Don't manually guess the correct parameters

Although we can visually estimate the slope and intercept, the purpose of the machine-learning example is to demonstrate how the algorithm learns them.

Start with reasonable initial values and let the optimization process improve them.

### 16.4 Keep the computational graph concept in mind

-------------------code----------------------

  ↓

  ↓
Operation
  ↓
Operation
  ↓
Output
-------------------code----------------------

Automatic differentiation works by traversing this computational structure to calculate gradients.
