*** 73. What Automatic Differentiation Is ***
# 1. What Is Automatic Differentiation?

**Automatic Differentiation (AD)** is a computational technique for calculating derivatives automatically through a sequence of mathematical operations.

It is especially useful in **machine learning**, where models can contain many inputs and extremely long chains of nested functions.

---

# 2. Different Names for Automatic Differentiation

The lecture gives several names:

| Name                              | Meaning                                               |
| --------------------------------- | ----------------------------------------------------- |
| **Automatic Differentiation**     | Full name                                             |
| **Autodiff**                      | Short form                                            |
| **Autograd**                      | Common name related to automatic gradient calculation |
| **Computational Differentiation** | Emphasizes the computational nature                   |
| **Algorithmic Differentiation**   | Another standard name                                 |
| **Reverse Mode Differentiation**  | Refers to the direction used by reverse-mode autodiff |

For this course, **Autodiff** and **Autograd** are especially important terms to recognize.

---

# 3. Why Not Just Use the Methods We Already Learned?

Before automatic differentiation, we studied two main approaches.

## 3.1 Numerical Differentiation

The **Delta method** is an example of numerical differentiation.

The basic idea is:

-------------------code----------------------
Take two nearby points
        ↓
Calculate Δy / Δx
        ↓
Make Δx increasingly small
        ↓
Approximate the derivative
-------------------code----------------------

For example:

-------------------code----------------------
def f(x):
    return x ** 2

x = 2
delta = 1e-6

derivative = (f(x + delta) - f(x)) / delta

print(derivative)
-------------------code----------------------

This gives an approximation close to:

-------------------code----------------------
4
-------------------code----------------------

### Problem

Numerical differentiation can introduce **rounding errors** when implemented computationally.

Therefore, although it works well for simple examples, it is not the preferred approach for large machine-learning computations.

---

# 4. Symbolic Differentiation

The second approach is **symbolic differentiation**.

This is what we primarily practiced in Segment 2.

For example:

[
y=x^2
]

Using the power rule:

[
\frac{dy}{dx}=2x
]

We could theoretically write software that implements rules such as:

* Constant rule
* Power rule
* Sum rule
* Product rule
* Quotient rule
* Chain rule

and then applies them to increasingly complicated expressions.

### Problem

This becomes **computationally inefficient** as functions become more complicated.

Machine-learning algorithms can contain:

-------------------code----------------------
Many operations
      ↓
Many nested functions
      ↓
Large computational graphs
      ↓
Very complicated derivatives
-------------------code----------------------

Symbolically manipulating all of those expressions can become impractical.

The lecture emphasizes that symbolic differentiation could work for simple functions, but becomes unsuitable for complex real-world machine-learning examples.

---

# 5. Why Automatic Differentiation?

Automatic differentiation provides a computationally convenient alternative.

According to the lecture, compared with the classical approaches, automatic differentiation:

* Avoids the rounding-error problem associated with numerical differentiation.
* Avoids the computational inefficiency of explicitly applying symbolic differentiation rules.
* Handles functions with **many inputs** well.
* Handles **higher-order derivatives** effectively.

This makes it particularly suitable for machine learning.

---

# 6. The Core Idea: Automatic Differentiation Uses the Chain Rule

The most important concept in this lecture is:

> **Automatic differentiation works by applying the chain rule to a sequence of arithmetic operations.**

The lecture describes this as a **forward pass of arithmetic operations**.

Consider two nested functions:

[
x \rightarrow u \rightarrow y
]

For example:

[
u=f(x)
]

and:

[
y=g(u)
]

The chain rule tells us:

The intermediate (du) effectively cancels:

-------------------code----------------------
dy   du
-- × --
du   dx

   ↓

dy
--
dx
-------------------code----------------------

This is the mathematical foundation that automatic differentiation uses.

---

# 7. Forward Pass

The forward computation proceeds from the input toward the output:

-------------------code----------------------
x
↓
u
↓
y
-------------------code----------------------

For example:

-------------------code----------------------
x = 2

u = x ** 2
y = u + 3

print(y)
-------------------code----------------------

The computation is:

-------------------code----------------------
x = 2
 ↓
u = 4
 ↓
y = 7
-------------------code----------------------

This is the **forward pass**.

---

# 8. How Automatic Differentiation Moves Through the Computation

Here is the important distinction.

When we manually applied the chain rule in Segment 2, we generally started from the **innermost function**.

For example:

-------------------code----------------------
x → u → y
-------------------code----------------------

we might start by differentiating:

-------------------code----------------------
u with respect to x
-------------------code----------------------

and then:

-------------------code----------------------
y with respect to u
-------------------code----------------------

Automatic differentiation, specifically **reverse-mode differentiation**, works in the opposite direction.

It proceeds:

-------------------code----------------------
y
↓
u
↓
x
-------------------code----------------------

This is why the lecture calls it **reverse mode differentiation**.

---

# 9. Reverse-Mode Automatic Differentiation

The basic idea is:

-------------------code----------------------
Forward computation:

x → u → y


Reverse differentiation:

y → u → x
-------------------code----------------------

The derivatives from the different stages are chained together.

Conceptually:

-------------------code----------------------
Forward:
x ─────→ u ─────→ y

Reverse:
∂y/∂x ← ∂y/∂u ← ∂u/∂x
-------------------code----------------------

The goal is ultimately to calculate:

[
\frac{dy}{dx}
]

---

# 10. Why Reverse Mode Is Computationally Useful

One of the major advantages described in the lecture is computational efficiency.

Suppose the forward pass is:

-------------------code----------------------
x → u → y
-------------------code----------------------

Automatic differentiation performs the derivative calculation backward:

-------------------code----------------------
y → u → x
-------------------code----------------------

The lecture explains that the additional computational cost is only a **small constant factor** compared with the original forward pass.

Conceptually:

-------------------code----------------------
Forward computation
        ↓
   relatively cheap
        ↓
Reverse-mode autodiff
        ↓
Only a small constant-factor overhead
-------------------code----------------------

This is one of the reasons automatic differentiation is so useful for machine learning.

---

We can represent the mathematical idea manually:

-------------------code----------------------
# Forward pass

y = u ** 3

print("x:", x)
print("u:", u)
print("y:", y)
-------------------code----------------------

The computation is:

-------------------code----------------------

The chain rule would conceptually give:

-------------------code----------------------

-------------------code----------------------

For this example:

-------------------code----------------------

-------------------code----------------------

and therefore:

-------------------code----------------------

-------------------code----------------------

The important point for this lecture is not manually calculating the derivative, but recognizing that **automatic differentiation can computationally track this chain**.

-------------------code----------------------

*** 74. Autodiff with PyTorch ***
# 1. Automatic Differentiation with PyTorch

This lecture is the first hands-on demonstration of **Automatic Differentiation (Autodiff)** using **PyTorch**.

The goal is simple:

> Calculate the derivative/slope of (y=x^2) at (x=5) using PyTorch, and verify that it matches the result we get manually.

---

# 2. The Mathematical Problem

We start with:

[
y=x^2
]

We want to find the slope at:

[
x=5
]

From the **power rule**:

[
\frac{dy}{dx}=2x
]

Therefore:

[
\frac{dy}{dx}\bigg|_{x=5}=2(5)=10
]

So we already know the expected answer:

-------------------code----------------------
Slope = 10
-------------------code----------------------

The purpose of PyTorch is to calculate this automatically rather than manually applying the derivative rules.

---

# 3. Import PyTorch

First, import the PyTorch library.

-------------------code----------------------
import torch
-------------------code----------------------

PyTorch is commonly thought of as a deep-learning library, but the lecture emphasizes that it is broader than just neural networks.

It can also be used for **automatic differentiation and calculus operations**.

---

# 4. Create the Input Tensor

We create a scalar tensor containing our (x) value:

-------------------code----------------------
x = torch.tensor(5.0)
-------------------code----------------------

The decimal point is intentional.

The lecture emphasizes using a **float tensor**, because many PyTorch operations work properly with floating-point tensors.

We can inspect it:

-------------------code----------------------
print(x)
-------------------code----------------------

Output:

-------------------code----------------------
tensor(5.)
-------------------code----------------------

---

# 5. Enable Gradient Tracking

This is the important new concept.

We want PyTorch to calculate derivatives with respect to `x`.

Therefore, we tell PyTorch to track the gradient of `x`:

-------------------code----------------------
x.requires_grad_()
-------------------code----------------------

This changes:

-------------------code----------------------
x.requires_grad
-------------------code----------------------

from:

-------------------code----------------------
False
-------------------code----------------------

to:

-------------------code----------------------
True
-------------------code----------------------

You can verify it:

-------------------code----------------------
print(x.requires_grad)
-------------------code----------------------

Output:

-------------------code----------------------
True
-------------------code----------------------

### Why do we need this?

PyTorch does **not** track gradients by default.

Gradient tracking requires additional memory, so it is only enabled when we need derivatives.

---

# 6. Perform the Forward Pass

Now implement our function:

[
y=x^2
]

In PyTorch:

-------------------code----------------------
y = x**2
-------------------code----------------------

Conceptually, the forward pass is:

-------------------code----------------------
x → y
-------------------code----------------------

or:

-------------------code----------------------
5 → 25
-------------------code----------------------

We can verify:

-------------------code----------------------
print(y)
-------------------code----------------------

Output:

-------------------code----------------------
tensor(25., grad_fn=...)
-------------------code----------------------

The important idea is that PyTorch has tracked the operation that produced `y` from `x`.

---

# 7. Gradient Tracking Is Contagious

This is an important concept from the lecture.

Because `x` has gradient tracking enabled:

-------------------code----------------------
x.requires_grad_()
-------------------code----------------------

tensors created as a result of operations involving `x` will also track the necessary gradient information.

For example:

-------------------code----------------------
y = x**2
-------------------code----------------------

PyTorch knows that `y` was created from `x`.

Therefore, it has enough information to work backwards from `y` toward `x`.

Conceptually:

-------------------code----------------------
Forward:

x ──────→ y
5         25


Backward:

dy/dx
←───────
-------------------code----------------------

This is the basis of Autodiff.

---

# 8. Calculate the Derivative with `backward()`

Now we perform automatic differentiation.

-------------------code----------------------
y.backward()
-------------------code----------------------

The `backward()` method tells PyTorch to work backwards from `y` and calculate the gradients.

In this example, we want:

[
\frac{dy}{dx}
]

PyTorch therefore follows the computational path:

-------------------code----------------------
y → x
-------------------code----------------------

and calculates the gradient automatically.

---

# 9. Retrieve the Gradient

After calling:

-------------------code----------------------
y.backward()
-------------------code----------------------

we can access the gradient stored on `x`:

-------------------code----------------------
print(x.grad)
-------------------code----------------------

The result is:

-------------------code----------------------
tensor(10.)
-------------------code----------------------

Therefore:

-------------------code----------------------
dy/dx = 10
-------------------code----------------------

This matches our manual calculation exactly.

---

# 10. What PyTorch Did

Let's compare the two approaches.

### Manual differentiation

We started with:

-------------------code----------------------
y = x²
-------------------code----------------------

Applied the power rule:

-------------------code----------------------
dy/dx = 2x
-------------------code----------------------

Substituted:

-------------------code----------------------
x = 5
-------------------code----------------------

Result:

-------------------code----------------------
dy/dx = 10
-------------------code----------------------

### PyTorch Autodiff

We:

-------------------code----------------------
x = torch.tensor(5.0)
x.requires_grad_()

y = x**2

y.backward()

print(x.grad)
-------------------code----------------------

Result:

-------------------code----------------------
10
-------------------code----------------------

So both approaches produce the same result.

---

# 11. Why This Becomes Powerful in Machine Learning

The example is intentionally extremely simple:

-------------------code----------------------
x → x² → y
-------------------code----------------------

But the same idea can be applied to much more complicated computational chains.

For example:

-------------------code----------------------
x
 ↓
function 1
 ↓
function 2
 ↓
function 3
 ↓
...
 ↓
function 1000
 ↓
y
-------------------code----------------------

Manually differentiating hundreds or thousands of nested operations would be extremely difficult.

PyTorch can track the computational operations and then use:

-------------------code----------------------
y.backward()
-------------------code----------------------

to calculate the gradients automatically.

This becomes particularly useful in machine learning and deep learning.

# 15. Best Practices and Important Notes

### 15.1 Use floating-point tensors

For differentiation, follow the lecture's approach and use:

-------------------code----------------------
torch.tensor(5.0)
-------------------code----------------------

rather than:

-------------------code----------------------
torch.tensor(5)
-------------------code----------------------

The decimal makes the tensor floating-point.

### 15.2 Enable gradients only when needed

Gradient tracking consumes additional memory.

Use:

-------------------code----------------------
x.requires_grad_()
-------------------code----------------------

when you actually need to calculate derivatives.

### 15.3 `backward()` calculates gradients

The key operation is:

-------------------code----------------------
y.backward()
-------------------code----------------------

It propagates the gradient backward through the operations that produced `y`.

### 15.4 `.grad` contains the result

After:

-------------------code----------------------
y.backward()
-------------------code----------------------

retrieve the gradient using:

-------------------code----------------------
x.grad
-------------------code----------------------

For this example:

-------------------code----------------------
x.grad = 10
-------------------code----------------------

### 15.5 Understand the forward/backward relationship

Think of Autodiff as two stages:

-------------------code----------------------
FORWARD PASS

x → operations → y


BACKWARD PASS

y → operations → x

        ↓

     gradients
-------------------code----------------------

This forward/backward structure is fundamental to machine learning.

---

# 16. Full Final Code

-------------------code----------------------
import torch

# Create the input tensor
x = torch.tensor(5.0)

# Enable gradient tracking
x.requires_grad_()

# Forward pass: y = x²
y = x**2

# Automatic differentiation
y.backward()

# Display the result
print("x:", x)
print("y:", y)
print("dy/dx:", x.grad)
-------------------code----------------------

Expected output:

-------------------code----------------------
x: tensor(5., requires_grad=True)
y: tensor(25., grad_fn=<PowBackward0>)
dy/dx: tensor(10.)
-------------------code----------------------

# 17. Summary

The main lesson is how to use **PyTorch Autodiff** to calculate derivatives automatically.

The complete process is:

-------------------code----------------------
Create x
   ↓
Enable requires_grad
   ↓
Perform forward calculation
   ↓
Call backward()
   ↓
Read x.grad
-------------------code----------------------

For:

[
y=x^2,\quad x=5
]

the derivative is:

-------------------code----------------------
dy/dx = 10
-------------------code----------------------

PyTorch obtains the same answer automatically.

The most important code to remember is:

-------------------code----------------------
x = torch.tensor(5.0)
x.requires_grad_()

y = x**2
y.backward()

print(x.grad)
-------------------code----------------------

This simple example is the foundation for using automatic differentiation in much larger machine-learning computational graphs.
